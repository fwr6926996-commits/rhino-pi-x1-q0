# 运行结果与解释范围

实测日期：2026-11-04。硬件为借测 X1，用户空间 Ubuntu 22.04.2/rootfs 50，AidLite 2.5.0.284。PCB 修订号未取得清晰证据，保持未确认。

五次运行分别为 ONNX CPU 样例、TFLite DSP 首次失败、同模型 CPU 对照、独立 strace 诊断、既有 aidlux 普通账号 DSP 配置运行。实际参数和样本见[机器可读记录](../evidence/results.json)。

ADB uid=2000 下的 DSP 路径在加载阶段报 110031，实际调用 0 次；strace 中两个 RPC 节点各 4 次 EACCES，缺失的 /dev/cdsprpc-smd 路径 4 次 ENOENT。普通动态库搜索失败后存在成功路径，不能据 ENOENT 一概判断缺库。

既有 aidlux uid=1007，含 system(1000) 组。在同一组冻结资产下，DSP 配置完成加载、10 次调用和结果图，未出现先前 delegate 错误或 CPU fallback 标记。实际使用普通账号，没有 root、chmod 或 SDK 更新。账号变化也改变 HOME/组/会话环境，不能据此确定单一权限位是唯一根因。

成功样例均报告 3 人、1 辆公交车，结果图已在本地目视检查；没有独立参考张量、标注集精度验收或逐节点硬件覆盖。检测图依赖第三方样例素材，本仓库不再分发。未见 fallback 标记和低延迟都不足以单独证明零 CPU 工作。

10 次 invoke 的观察均值为 ONNX CPU 149.03 ms、TFLite CPU 78.70 ms、普通账号 TFLite DSP 配置 1.56 ms。time.time() 不是已校验的单调性能基准，调用数少且条件未配对；没有 P95/P99、持续性能、芯片加速倍数或机器人实时保证。

公开摘要和哈希提供追溯入口，不是原始日志的独立替代证明。任何正式精度、稳定性或硬件加速结论都需要单独实验和审阅。
